# 只做无状态的 stdio 代理，不落任何本地数据

本项目的全部状态都留在 XXL-JOB 调度中心，自身不建库、不缓存任务配置、不持久化执行历史；传输只用 stdio，不用 HTTP/SSE。

**为什么**：MCP 客户端通常以子进程方式拉起 server，生命周期由客户端掌控，进程随时可能被重启。一旦本地有状态，就要处理「进程重启后状态与调度中心不一致」的同步问题——而这部分能力调度中心本来就提供了，重复实现只会引入新的失配来源。同理选 stdio 而非 SSE：stdio 的权限边界天然继承客户端（不需要额外开端口、配鉴权），部署成本接近于零。

**代价**：无法跨客户端共享会话缓存，每次进程启动都要重新登录一次；也无法做本地只读缓存来加速批量查询。
