# 改任务走「读取 → 合并 → 写回」，而不是部分字段提交

`update_job` 先 `getById` 拿全量配置，只覆盖调用方显式传入的字段，再整体提交完整表单。

**为什么**：Admin 的 `/jobinfo/update` 是整体覆盖语义——它接收的是一整行表单，缺哪个字段就把哪一列写成空。如果直接把调用方传入的部分字段提交上去，「只改 Cron」这个动作会顺手把 JobHandler、负责人、告警邮箱全部清空。这类数据丢失不可逆（配置被覆盖后没有历史版本可回滚），所以宁可多两次 HTTP 往返。

**代价**：一次修改产生 3 次网络往返（读、写、再读确认）；并发修改同一任务时，后写的一方会覆盖先写的一方（没有乐观锁）。考虑到定时任务配置的修改频率，这个代价可以接受。

**替代方案**：不采用「只传变更字段」，因为它依赖 Admin 的 update 接口做字段级合并，而该语义在各版本／二开版之间并不一致。
