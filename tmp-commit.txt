feat(cli): 新增 help 与 add 子命令，init 支持继续添加

## 改动

### 1. help

multi-xxl-job-mcp help / --help / -h 输出命令列表、配置文件路径与退出码约定。

顺带修正一个隐患：此前任何非 init 参数都会静默启动 stdio 服务，
foo start 这类笔误会被忽略且毫无反馈。现在未知命令一律报错并指向 help。

### 2. add lib 在已有配置上追加

i 选择：在现有系统下加一个环境（多系统时先让用户选目标系统）
s 选择：加一个新系统及其首个环境

关键约束：
- 只改目标节点，其它系统、其它环境、alias 全部原样保留
- 配置文件不存在时报错而非新建（那是 init 的职责）
- 现有配置解析失败时停下来，不贸然写回，否则会冲掉用户手写内容
- 写完同样做两道自检（渲染后按配置层校验、落盘后回读）

### 3. init 支持继续添加

收集完第一条后询问 i/s/d。两个设计决定：
- 累积后一次性写入：边问边写的话中断会留下半数配置
- 输入耗尽按结束处理而非抛错：否则等于给 init 强加必答的第六问，
  会打断所有只给必要回答的脚本化调用（这是最初实现踩到的坑）

## 实现要点

- 抽出 collectConnection() 供三种场景复用，保证提问与默认值一致
- 新增纯函数 parseConfigText / addInstanceToConfig / addSystemToConfig / renderConfigDocument
- 同名系统已存在时追加环境而非替换整个系统：替换会静默丢掉其它环境与 alias
