docs: 清理本地信息，统一为可移植表述

## 审查范围

本仓库是公开项目，全量扫描了一遍本地信息与机器相关表述：

| 检查项 | 结果 |
|---|---|
| 绝对路径 / 家目录路径 | 1 处（AGENTS.md）|
| 用户名 / 邮箱 / 真实姓名 | 仅 package.json 的 author 与 GitHub 提交身份，属正常公开信息 |
| 内网 IP / 真实主机名 | 无 |
| 真实凭据 / token | 无 |
| 被跟踪的本机产物 | 仅 .codegraph/.gitignore（仓库约定要求提交）|
| 本机工具链痕迹（Homebrew 路径等）| 无 |

## 改动

### 1. AGENTS.md：去掉硬编码的绝对路径

原文把某台机器上的 `projectPath=/Users/<user>/Projects/...` 写死在文档里。
改为「取当前仓库根目录的绝对路径（即 pwd 的输出）」，并注明不要写死路径的原因。

### 2. docs/specs/0001：标注实现现状

这份设计文档保留原始决策语境，但有 3 处已与实现不符，照它读会误判：

| 文档写的 | 实际 |
|---|---|
| 配置路径按平台原生惯例分三套 | 三平台统一 ~/.config（ADR-0004）|
| list_instances 返回 username | 不返回 username，也不返回任何凭据 |
| 状态「实现未开始」| 已全部实现并合并 |

处理方式是在文件头加一个「实现现状与本文的差异」小节，而**不改动原文**——
设计文档的价值恰恰在于保留当时的决策语境，直接重写会让后来的读者看不到设计演进。
